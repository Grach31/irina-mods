# Серверная проверка фотографий Moda 3.0

## Запрос до сохранения карточки

Редакция выбирает товары, сверяет название, цвет, цену и ссылку на официальную страницу. Для каждой новой карточки или замены товара создаёт через GitHub в `main` файл `moda/preflight/<request_id>.json`. Это запрос на проверку. Черновик на этом этапе ещё не записывается. Запросы неизменяемые. Для повтора нужен новый `request_id`. Используйте уникальный ID, например дату и UUID в нижнем регистре. Для `request_id`, `cards[].id` и `items[].key` допустим шаблон `[a-z0-9][a-z0-9_-]{0,95}`.

```json
{
  "schema_version": 1,
  "cards": [
    {
      "id": "2026-11-26-mix-example",
      "items": [
        {
          "key": "item-1",
          "product_url": "https://www.gate31.ru/product/sumka-polumesyats-dublin"
        }
      ]
    }
  ]
}
```

Допустимы 1–2 карточки, по 1–3 товара на карточку. `cards[].id` — будущий ID черновика. `items[].key` уникален в пределах карточки. Необязательный `preferred_images` задаёт до трёх URL в порядке предпочтения. Сервер пробует такой URL только если нашёл его в галерее продукта. Без предпочтений он сам извлекает фотографии из структурированных данных и размеченной галереи. Новый ежедневный черновик по-прежнему должен содержать три вещи. Запрос на один товар подходит для повторной проверки или правки.

Отдельный GitHub Actions workflow **Moda photo preflight** запускается при добавлении файла. Для чтения ответа достаточно обычного доступа к файлам GitHub. Отправка запроса и чтение ответа не требуют исходящих запросов из ChatGPT к магазинам или CDN. Наличие и размеры товара не проверяются.

## Результат и замены

Дождитесь `moda/results/<request_id>.json` в `main`. Пока файла нет, запрос ожидает обработки. Утраченный или упавший запуск проверяйте по коммиту запроса в Actions. `invalid_request` с `message` означает ошибку формата. У результата `completed` сверяйте `schema_version: 1`, `request_id`, `request_sha256` (SHA-256 точных байтов запроса, если доступны для сверки), ID карточки, ключ и `product_url` каждого товара с отправленным запросом.

- Карточка `verified` означает, что все запрошенные товары прошли проверку. `needs_replacements` требует обработки указанных позиций. Вторая карточка имеет собственный результат и может быть сохранена независимо.
- Товар `verified` содержит `photo.img` (устойчивый HTTPS-адрес нормализованного JPEG), `sha256`, исходный `source_url`, фактический `final_url`, `http_status`, `content_type`, `bytes`, `width`, `height`, `attempts`. Размер и разрешение относятся к скачанному оригиналу с учётом EXIF-ориентации. Если у товара несколько цветовых вариантов, редакция сверяет выбранное фото с нужным цветом.
- Товар `replace_product` содержит `failures` с `url`, `code`, `http_status`, `attempts`, `message`. После исчерпания официальной галереи замените именно эту позицию и отправьте новый запрос с тем же ID карточки. Успешные позиции можно брать из прежних ответов той же карточки. Если сбой связан с инфраструктурой или нарушенным форматом запроса, повторите проверку с новым ID после устранения причины.

Проверка требует HTTP 200, корректный MIME для JPEG/PNG/WebP, размер 3 000–12 000 000 байт и полное декодирование неподвижного изображения. Обе стороны должны составлять минимум 300 пикселей при максимуме 35 млн пикселей. Сервер ограничивает длинную сторону сохраняемого JPEG 2 000 пикселями и сохраняет минимум 300 по короткой. Тайм-ауты, временные сетевые ошибки и HTTP 408/425/429/500/502/503/504 дают до трёх попыток на URL. При отказе, 404, повреждении или неподходящих метаданных сервер переходит к следующему фото, максимум шесть фото из галереи.

## Сохранение и подтверждение доставки

Снимки и результаты появляются атомарно в Git. Хранилище `drafts/photos/moda/<sha256>.jpg` адресуется по содержимому. Сохранённые снимки и квитанции следует сохранять, пока на них ссылаются черновики или опубликованные материалы.

В каждой позиции `drafts/<id>.json` сохраните существующие `name, price, url, shop`, запишите `img = photo.img` и добавьте `image_preflight = request_id` того ответа, в котором проверена позиция. `url` должен точно совпадать с `product_url`. Сборщик сопоставляет карточку, товар, URL и хеш с квитанцией и использует JPEG из Git. Для старых черновиков с прямыми ссылками сохранён прежний путь сборки. Проверенную карточку коммитьте отдельно от второй. При исправлении подписи сохраняйте поля товара и фото целиком.

Для каждого ID дождитесь Pages workflow этого коммита или потомка. В `catalog.json` должны совпадать `id`, `ready: true` и `revision` (SHA-256 текущего файла черновика). Проверьте HTTP 200 и декодирование `media/<id>.jpg`, его SHA-256 должен совпасть с `media_sha256` из каталога. Подтвердите запись `MYSPACE_DELIVERY_BUILD` для того же ID и ревизии и успешный `MYSPACE_DEPLOYMENT_RECONCILED` этого релиза. Если Pages недоступен напрямую, используйте предусмотренную в AGENT.md сверку опубликованной доставки через запись My Space по `source_id` и `version`. Публикация в Telegram по-прежнему выполняется только после явного ручного одобрения.
