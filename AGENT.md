# Stambo.i / My Space — технический контракт
Репозиторий `Grach31/irina-mods`, основная ветка `main`.

## 1. Границы ответственности
GPT → GitHub → техническая сборка → My Space → ручное одобрение → Telegram.
Редакционные задания, расписание, количество материалов, проверка фактов, цен,
фото, прав и стиля принадлежат действующим GPT-автоматизациям. GitHub проверяет
формат и собирает доставку; повторной редакционной проверки после GPT нет.
Работают три редакционные задачи:
- «Moda — ежедневные подборки»: товарные черновики и запросы правок.
- «GPT-редакция — My Space»: только Style Time Machine и Reels Studio,
  файлы `miniapp/style-time-machine.json`, `miniapp/reels-studio.json`,
  собственные изображения и статусы `history/reels`.
- «Fashion Daily и Trend Radar»: только Fashion Daily и Trend Radar,
  файлы `miniapp/fashion-daily.json`, `miniapp/fashion-archive/YYYY-MM-DD.json`,
  `miniapp/trend-radar.json`, собственные изображения и статусы `fashion/trends`.
  Fashion Daily выполняется ежедневно; Trend Radar и его статус — только по понедельникам
  по московской дате. Расписание задано в автоматизациях.
Создание и правки Moda выполняет только задача Moda; другие редакции не меняют
`drafts/`, `editorial/edit-completions/` и статусы Moda.
Каждая задача обрабатывает только свои рубрики, сохраняет только свои материалы
и статусы поверх свежей main, не перетирая чужие коммиты.
Дополнительных исполнителей/автоматизаций без отдельного задания не создавать.
Дополнительные воскресные истории моды не создавать; ежедневную Style Time Machine не менять.
Telegram — только по явному решению авторизованного модератора в My Space.
`queued` означает «Ожидает одобрения». Коммит, деплой, одобрение и отправка — разные стадии.
Не менять авторизацию Supabase Auth, доступы, защиту от дублей и публикационные статусы.
В редакционном запуске не менять `bot/`, `state/`, `data/`, workflows и сервер.

## Правила Moda
Единственный источник инструкций редактора Moda — действующее задание
«Moda — ежедневные подборки»: магазины, критерии, формат, обработка замечаний,
сохранение и короткая проверка результата заданы в нём полностью.
Для запуска Moda отдельное чтение этого файла не требуется. Архив за 14 дней
Moda не проверяет; читает только сегодняшние материалы и конкретные черновики
для новых замечаний. Техническая сборка и ручное одобрение Telegram сохраняются.

## 2. Пути и идентификаторы
- `drafts/<id>.json`: ID совпадает с именем файла, без `/`, `\`, начальной точки.
  Индексы в `drafts/` не хранить. `drafts/img/*.jpg` — сохранённые визуалы;
  актуальный Pages JPG: `https://grach31.github.io/irina-mods/media/<id>.jpg`.
- `miniapp/fashion-daily.json`, архив `miniapp/fashion-archive/YYYY-MM-DD.json`;
  `miniapp/style-time-machine.json`, `miniapp/reels-studio.json`, `miniapp/trend-radar.json`.
- Для остальных редакционных рубрик до записи читать актуальные JSON и архив за 14 дней.
  Сохранять старые записи, постоянные ID и схемы; не повторять сегодняшний выпуск и сюжеты.
  Для Moda действуют только инструкции её автоматизации.
- Старый Python-сборщик удалён: `data/candidates.json` и `data/sheets/` не нужны.
  `data/requests.json` — исторические запросы, `state/state.json` — техническая история,
  а не универсальное подтверждение публикации.

## 3. Moda
Редакционные инструкции и схема товарного черновика перенесены в автоматизацию
«Moda — ежедневные подборки». Действующие генераторы и серверные контракты не меняются.

## 4. JSON редакционных рубрик
Общий контейнер — `{updated_at,items:[...]}`, постоянный уникальный `id` у каждой карточки.
- Fashion Daily: `edition_date`; карточка `id,title,date,published_at,region` (`ru/world`),
  `source,url,summary,article_sections`. Для старых записей без `published_at` используется `date`.
  `telegram_text` — подготовленный GPT текст для
  ручной публикации, для старых записей fallback `summary` + `why`.
  Для новых новостей фото готовить автоматически в том же редакционном запуске,
  до коммита: `image_url,image_alt,image_source`/`image_credit`,
  `image_source_url,image_rights`. Сначала искать подходящее фото на странице
  первоисточника: `og:image`, `twitter:image`, JSON-LD `image`, основное фото статьи.
  Проверять прямой HTTPS URL, декодирование изображения и соответствие сюжету.
  `publisher_preview_hotlink` — поддерживаемое внешнее превью издателя по ссылке,
  не лицензированный локальный файл; отсутствие лицензии на локальное копирование
  само по себе не основание пропускать такое превью. Сохранять атрибуцию и ссылку
  на статью; не скачивать для повторного размещения без подтверждённых прав,
  не обходить запреты источника и не подставлять случайные изображения/логотипы.
  Если фото недоступно: другое фото статьи → другой первоисточник того же сюжета
  → другая проверенная новость с фото. `no_external_image` и текстовая обложка
  остаются совместимым аварийным вариантом для старых записей и реальных сбоев,
  а не нормальным завершением нового выпуска: указать адреса/ошибки попыток,
  итог `fashion blocked/images`, повторить поиск самостоятельно в следующем запуске.
  Сегодняшняя новость без фото требует дозаполнения существующего ID, а не дубля.
  Готовность Fashion проверять по опубликованному JSON и доступности самих фото.
  Для мобильного показа предпочитать подходящее оптимизированное фото из статьи тяжёлой
  социальной PNG-обложке. Допустимы проверенные резервные превью в
  `image_fallbacks:[{url,alt,credit,source_url,rights:"publisher_preview_hotlink"}]`;
  каждая ссылка должна соответствовать этому же сюжету и иметь собственную атрибуцию.
  Приложение пробует резервы и ограниченный повтор загрузки при ошибке.
  Когда доступен браузер, проверять `naturalWidth > 0` именно в карточке и статье,
  а не только скачивание файла отдельно. Просмотр на iPhone подтверждать только фактически.
- Reels: `id,title,category,format,duration,hook,script,shots,cta`;
  `sources:[{title,url}]` для новостного сценария.
- Style Time Machine: `id,title,year,period,description,then,now,category,source_url`,
  `photos:[{url,caption,credit,source_url}]` (минимум одно фото).
  Ручная публикация сохраняет полный текст и фото; разбиение выполняет сервер.
- Trend Radar: контейнер также `period_label,intro`; карточка
  `id,title,category,status,summary,stylist,evidence,sources:[{title,url,date}],added_at,updated_at,last_checked_at`,
  `image_url,image_alt,image_source_url,image_credit,image_license`; `featured:true` максимум у одной.
  Сохранять ID и `added_at`; при проверке без изменений менять только `last_checked_at`.

## 5. Справочник Trend Radar для действующей GPT-задачи
Категории: Цвета, Фактуры, Силуэты, Вещи, Обувь, Аксессуары, Принты,
Стайлинг, Бьюти, Микротренды, Антитренды, Подиум.
Статусы: Появляется / Набирает силу / На пике / Угасает / Наблюдаем.
Источники: первичные показы/бренды, Vogue Runway/street style, WWD/FashionUnited/BoF,
Lyst Index (спрос), Pinterest Predicts/Trends и Google Trends (интерес).
GPT различает дату, географию, сезон показа/ношения и прогноз/спрос, сверяет предыдущую
неделю и горизонт 4–12 недель. Уверенный статус требует двух независимых типов сигналов;
при нехватке — Наблюдаем. Старая иллюстрация не доказывает актуальный показ или рост.
Это справочник для GPT, не дополнительные проверки GitHub.

## 6. Техническая сборка
Pages workflow проверяет JSON, обязательные поля и локальные изображения,
генерирует JPG, каталог и манифест уведомлений, развёртывает Pages и уведомляет My Space.
Не коммитить результаты генератора обратно в main. Ошибка одного JPG не должна
блокировать независимые рубрики; неактуальный JPG не даёт `ready` (см. раздел 9).

## 7. Подтверждение результата
Готовность: конкретный успешный Pages workflow, доступный материал и ожидаемые
`ready/revision` в опубликованном `catalog.json`. Визуальную проверку Safari/iPhone
подтверждать только если она реально выполнена. При сбое указывать этап и ошибку;
не считать очередь сборки публикацией. Telegram `sent_at` от редакционной задачи не требовать.
Редакционные попытки замены и приоритеты задаются GPT-автоматизацией.

Если среда GPT не читает Pages, подтверждать доставку можно через существующие
GitHub и Supabase: в логе build найти `MYSPACE_DELIVERY_BUILD` с нужным `source_id`,
`version` и `delivery` (`release_sha,ready,revision,media_sha256`); проверить успешный
deploy этого релиза и `MYSPACE_DEPLOYMENT_RECONCILED`. Затем прочитать
`public.myspace_notification_events` по тому же `source_id` и `version`: сервер
сохраняет `payload.delivery` после получения и сверки опубликованного манифеста
с каталогом. Ревизия должна совпадать с SHA-256 актуального JSON, а событие —
с нужной версией, не только ID. Для старых событий без `payload.delivery`
сверять `version` с записью build. Это подтверждает техническую доставку,
не визуальный просмотр Safari и не одобрение Telegram. Ошибка доступа к Pages
не должна останавливать создание и сохранение уже проверенных материалов.

## 8. Уведомления и подтверждение правок
- Уведомления доставляет сервер My Space. Не отправлять их вручную и не создавать дополнительные GPT-автоматизации.
- Все новые карточки miniapp JSON должны иметь постоянный `id`. Существующие ID не менять.
- В конце обработки каждой рубрики фиксировать итог: `python scripts/report_editorial.py <moda|fashion|reels|history|trends> <ready|blocked> <ok|sources|images|access|validation|other>`. `blocked` допустим только после предусмотренных попыток; `ready` только при проверенном результате. Коммитить `editorial/status/*.json` вместе с материалами или итогом неудачного запуска. Это вход системы уведомлений, не отправка в Telegram. В дни без плановой проверки Trend Radar его статус не менять.


## 9. Технические гарантии Moda
Инструкции вызова claim/verify/submit/release и подтверждения правок находятся
непосредственно в автоматизации Moda. Серверный механизм остаётся действующим.
JPG строятся в артефакте Pages без обратных коммитов генератора.
Изменение товара/цены/фото пересобирает JPG; исправление только подписи не меняет визуал.
Обычные товарные подборки публикуются только с явно одобренной ревизией.
uncertain требует ручной сверки канала; повторная отправка запрещена.
Отсутствие прав Telegram-бота не является сбоем подготовки материалов.
