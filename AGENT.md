# Stambo.i — GPT-редакция / бот-доставщик (архитектура v2, 13.11.2026)

> **Приоритетный регламент.** Этот раздел имеет приоритет над устаревшими упоминаниями Claude и процедурой полного перечитывания архива ниже. Подробные требования к JSON, HTML, фотографиям, источникам и модерации из последующих разделов сохраняются.

## Разделение ответственности

- **GPT в ChatGPT (плановая редакционная задача)**: единственный редактор ежедневных подборок, образов, новостей и воскресной истории; читает запросы и правки, проверяет источники и визуально фотографии, составляет финальные JSON, сохраняет в `drafts/` на `main`. Для просьб о лук-роликах 2–6 фото сохраняется отдельная задача Higgsfield.
- **GitHub Actions / Telegram-бот**: только технический транспорт и рендеринг: получает уже подготовленные черновики, генерирует превью при `hold:true`, отправляет материалы Ирине, обрабатывает «Опубликовать», «Правки», «Отменить», публикует только по явному одобрению, записывает статусы и входящие просьбы. Бот не выбирает товары, не пишет редакционные тексты и не публикует самостоятельно.
- **Ирина**: единственный субъект финального решения о публикации. `slot:null` для всех новых черновиков.
- **My Space → Moda**: готовый черновик без `hold` появляется в каталоге со статусом `queued` ещё до Telegram-доставки; этот статус не даёт права публикации из Safari. После Telegram-подтверждения статус становится `sent`, и только тогда разрешается согласование. Тот же черновик отображается в Telegram Mini App и в отдельной Safari/PWA версии My Space; не создавай отдельные копии черновиков для разных интерфейсов. Источник данных один: `drafts/*.json` и статусы `state/state.json`; публичный каталог `miniapp/catalog.json` формирует `scripts/build_miniapp_catalog.py` при развёртывании Pages. Согласование через Safari допускается только после проверки серверной сессии и прав модератора; Telegram использует авторизованного пользователя. Публикация по-прежнему только после явного одобрения Ирины, без дублей по `id`.
- **Доставка в два интерфейса**: GitHub Actions запускает короткие транспортные циклы каждые 15 минут; GPT не выполняет редакцию внутри бота. после сохранения GPT проверяет не только Telegram `sent_at`, но и появление черновика в каталоге Moda после обновления Pages. Коммит в GitHub, отправка в Telegram и отображение в Safari — три разные проверки; если хотя бы одна не подтверждена, так и сообщай.

## Алгоритм редакционного запуска

1. Получи московское время, актуальные `data/requests.json`, `state/state.json`, `data/candidates.json` и дерево GitHub одним запросом `git/trees/main?recursive=1`. При `truncated:true` отдельно прочитай дерево `drafts/`. Не сканируй весь архив.
2. Отфильтруй черновики по имени за последние 14 календарных дней и адресные ссылки из новых просьб, правок и `held`. Читай только эти JSON небольшими параллельными пачками; составь временный Set нормализованных URL/артикулов из `items` и `looks[].items`. Для news сравни события за 7 дней. Не добавляй индексный JSON в `drafts/`: он будет принят ботом за публикацию.
3. В первую очередь обрабатывай `requests.status=new` (кроме лук-роликов 2–6 фото), `edit_requested`, `held.preview_ready` и ошибки доставки. Затем **только с 08:00 до 11:00 МСК** создавай недостающие ежедневные рубрики: две picks (смешанная и один магазин, вторник/пятница — dream), looks, news, воскресенье — history.
4. Для picks/looks используй только проверенные кандидаты. Контактные листы `data/sheets/*.jpg` обязательно получай через GitHub `fetch_file encoding=base64` и **визуально просматривай**; текстовое описание не заменяет проверку. Без полной проверки повторов за 14 дней не выпускай picks/looks.
5. Каждую независимую подтверждённую рубрику сохраняй сразу отдельным корректным JSON в `drafts/`, даже если другая рубрика заблокирована. Для `hold` проверяй итоговые `drafts/img/*.jpg` визуально и снимай hold только при проверенном качестве и фактах. Новость без подтверждения заменяй другой, а не блокируй весь выпуск.
6. После записи сверяй commit SHA, затем проверяй `state/state.json` на факт отправки в Telegram. **Коммит ≠ доставка**. При технической ошибке сообщай конкретную причину и список несохранённых/недоставленных рубрик; не заявляй об успехе заранее.
7. Не выдумывай цены, наличие, опыт Ирины, лицензии, источники или результаты проверки. Не используй Wildberries. Не изменяй код бота, workflow, `data/` или `state/` в обычном редакционном цикле.

## Надёжность и ограничения

- Если GitHub API ограничен, не повторяй полные запросы и не делай вид, что дедупликация завершена; продолжай независимые новости, просьбы и правки.
- Повторная попытка доставки должна быть идемпотентной по `id`: уже отправленные материалы нельзя повторно отправлять Ирине.
- Уведомляй владельца о неготовых материалах с точной причиной, а не фразой «нечего делать».
- Изменение архитектуры и бота выполняется отдельно от редакционного цикла, с тестами и без обхода модерации.

# Как Claude готовит посты для канала Stambo.i

Канал Ирины (стилист, @stamboir) о моде: подборки вещей российских брендов, её находки, рубрики «История моды»
и «Новости модных домов».
Claude только **кладёт черновики** в папку `drafts/`. Всё остальное делает бот на GitHub (`.github/workflows/bot.yml`):
отправляет черновик Ирине с кнопками ✅ / ✏️ / ❌, публикует после её одобрения, складывает её просьбы в `data/requests.json`.
Ничего не публикуется без кнопки Ирины. Пост выходит в канал сразу после её ✅ (без расписания), поле `slot` всегда `null`.

## Что делать при каждом запуске

1. `git pull`. Посмотри `state/state.json` (статусы черновиков) и `data/requests.json`.
2. **Просьбы Ирины** — записи со `"status": "new"`: на каждую сделай черновик с `"request_id"` этой просьбы и `"slot": null`. Если к просьбе приложено фото (`photos`), посмотри его (Read). Просьба с 2–6 фото вещей и словами про лук/образ/ролик — это **лук-ролик**, см. раздел «Лук-ролик по просьбе Ирины».
3. **Правки** — черновики в `state.json` со `"status": "edit_requested"`: в поле `comment` написано, что поправить
   (иногда есть `comment_photos`). Сделай новую версию с новым id и `"revision_of": "<старый id>"`.
4. **Ежедневные посты** — если сейчас 8:00–11:00 МСК, проверь по `drafts/` каждую рубрику отдельно: чего из списка
   ниже с сегодняшней датой и `"daily": true` ещё нет, то и сделай (подборки ищи по `"type": "picks"`, новости — `"news"`,
   историю — `"history"`):
   - 2 подборки (`"type": "picks"`, `"daily": true`): **одна смешанная** (вещи 2–3 разных магазинов на одну тему)
     и **одна из одного магазина**.
   - Вторник и пятница: подборка одного магазина — «вещь мечты» (Askent, Ushatava, 12 Storeez или IDOL, 1–2 вещи); смешанная остаётся.
   - Каждый день: дополнительно «Новости модных домов» (`"type": "news"`, `"daily": true`), см. ниже.
   - Каждый день: дополнительно **карусель образов** (`"type": "looks"`, `"daily": true`), см. «Карусель образов».
   - Воскресенье: дополнительно «История моды» (`"type": "history"`, `"daily": true`).
   Повторы: не бери вещи, которые уже были в `drafts/` за последние 14 дней.
5. Положи файлы в `drafts/` (с фото Commons — сначала через `"hold"`, см. «История моды»), `git add drafts && git commit && git pull --rebase && git push`. Пуш сам запустит бота.
   Если ничего делать не нужно — ничего не коммить.

> по магазину 0 товаров или нет листа в `data/sheets/`, не бери его и скажи владельцу, что сборщик нужно поправить (`bot/shops.py`).

- `data/sheets/<Магазин>.jpg` — сетка фото с номерами `#i` (номер = индекс в списке магазина). **Обязательно посмотри лист
  перед выбором** и бери только вещи с чистым студийным фото в одном стиле (без надписей, коллажей, обрезанной головы крупным планом).
- **Wildberries не использовать никогда.** Lamoda недоступна. Только магазины из списка выше.
- В подборке 2–4 вещи с общей темой: «тёплое на зиму», «трикотаж», «к джинсам» и т.п.
  - **Подборка одного магазина** — все вещи одного магазина.
  - **Смешанная подборка** — вещи 2–3 разных магазинов из списка выше (Lime, Love Republic, 2MOOD, Sela, Zarina, Befree, STUDIO 29, ALL WE NEED; Askent/Ushatava/12 Storeez/IDOL можно
    добавить одной вещью). Чтобы коллаж был цельным, по контактным листам бери фото с похожим фоном и кадром
    (все в рост на светлом фоне и т.п.). В списке вещей в тексте после цены указывай магазин:
    `<a href="URL">Бомбер с мехом</a> — 11 999 ₽ · Lime`. В id отрази смесь, например `2026-10-19-mix-warm`.

## Формат черновика `drafts/<id>.json`

id: `ГГГГ-ММ-ДД-<короткое-слово>`, например `2026-10-19-lime-knit`. Файл назови так же, как id.

```json
{
  "id": "2026-10-19-lime-knit",
  "type": "picks",
  "daily": true,
  "slot": null,
  "items": [{"name": "Свитер из шерсти", "price": 7999, "url": "https://...", "img": "https://...", "shop": "Lime"}],
  "text": "HTML-текст поста"
}
```

История моды:
```json
{
  "id": "2026-10-25-history",
  "type": "history",
  "daily": true,
  "slot": null,
  "hold": true,
  "card": {"kicker": "ИСТОРИЯ МОДЫ", "year": "1947", "note": "79 лет назад", "title": "New Look Кристиана Диора",
           "images": [{"commons": "Christian Dior New Look 1947.jpg", "grayscale": true, "fy": 0.2}],
           "credits": ""},
  "text": "HTML-текст поста",
  "sources": ["https://... откуда факт"]
}
```

## Текст поста (голос Ирины)

- Коротко: 2–5 строк своими словами + список вещей. **Вся подпись не длиннее 900 символов** (лимит Telegram 1024).
- Тон личный и живой, как подруге: «прям любовь», «цена вопроса», «очень нравится мне этот вайб». 1–2 эмодзи, не больше.
- Не выдумывай факты о самой Ирине (что она купила, носит, где была), если она сама этого не написала в просьбе.
- Вещи — ссылками, коротко: `<a href="URL">Бомбер с меховой отделкой</a> — 11 999 ₽`, каждая с новой строки.
- Telegram HTML: только `<b>`, `<i>`, `<a href="">`. Экранируй `&`, `<`, `>` в обычном тексте.
- В конце можно вопрос к подписчицам.

Пример:
```
Новинки Lime: тёплое на зиму, которое не выглядит как «просто пуховик» 🍂

Бомбер с мехом в хаки — фаворит подборки, с джинсами и грубыми ботинками будет огонь

<a href="https://limestore.com/ru_ru/product/37113-8015_543_312_xaki">Бомбер с меховой отделкой</a> — 11 999 ₽
<a href="https://limestore.com/ru_ru/product/36392-3505_479_201_temno_koricnevyi">Куртка на искусственном пуху</a> — 13 999 ₽
```

## Карусель образов

Раз в день — карусель, как у популярных пабликов с образами: обложка с крупным заголовком и по слайду на каждый
**готовый образ целиком** (верхняя одежда + верх + низ + обувь/сумка/аксессуар). Бот сам рисует слайды-флэтлеи на
бежевом фоне (вещи без фона, с мягкой тенью, внизу подписи «вещь · магазин · цена») и отправляет Ирине альбомом;
после ✅ в канал уходит тот же альбом.
- 3–4 образа (максимум 9), в каждом 3–5 вещей (лучше 4). Порядок вещей в образе = раскладка на слайде:
  1) верхняя одежда (большое место слева сверху), 2) верх или аксессуар (справа сверху), 3) низ (справа снизу),
  4) обувь или сумка (слева снизу), 5) ещё одна мелочь (слева снизу рядом).
- Вещи только из `data/candidates.json` (Lime, Love Republic, 2MOOD, Sela, Zarina, Befree, STUDIO 29, ALL WE NEED, Askent, Ushatava, 12 Storeez, IDOL), **Wildberries никогда**.
  По контактным листам бери **предметные фото на однотонном светлом фоне без модели** (у Lime почти все такие,
  у Askent — сумки и обувь, у Ushatava — обувь, сумки, шарфы, перчатки): так вещи «вырезаются» и слайд выглядит
  как флэтлей. Фото на модели — только если без них образ не собрать.
- Каждый образ в одной гамме, у образа короткое название («Шоколад», «Графит и бордо»). Вещи не повторять
  с другими черновиками за 14 дней (разные цвета одной модели — можно, если иначе не собрать).
- Подпись: 1–2 строки вступления, затем по каждому образу строка `<b>1. Шоколад</b>` и вещи ссылками
  `<a href="URL">Пуховик</a> — 19 999 ₽ · Lime`, в конце вопрос («Какой образ ваш — 1, 2, 3?»).
  Видимый текст ≤ 900 символов (ссылки не считаются), поэтому названия вещей короткие.

```json
{
  "id": "2026-10-19-looks",
  "type": "looks",
  "daily": true,
  "slot": null,
  "cover": {"title": "ОБРАЗЫ", "subtitle": "на холодную осень и зиму"},
  "looks": [
    {"title": "Шоколад",
     "items": [{"short": "Пуховик", "name": "…", "price": 19999, "url": "https://…", "img": "https://…", "shop": "Lime"}]}
  ],
  "text": "HTML-текст поста"
}
```
`short` — короткое название для подписи на слайде. Можно положить с `"hold": true`, тогда бот нарисует слайды
в `drafts/img/<id>.jpg`, `<id>-2.jpg`, … не отправляя Ирине — посмотри их и сними `hold`.

## Альбом из готовых фото

`"type": "album"` — бот отправляет Ирине (и после ✅ публикует) готовые фото как есть, альбомом до 10 штук, без коллажа.
Фото кладутся в `drafts/photos/<id>-1.jpg`, `-2.jpg`… (или прямые ссылки), список — в `photos`.
`items` — вещи для текста и для проверки повторов (`price` может быть `null`, если цену не удалось проверить).

```json
{"id": "2026-10-27-gloria-jeans", "type": "album", "slot": null,
 "photos": ["drafts/photos/2026-10-27-gloria-jeans-1.jpg"],
 "items": [{"name": "…", "price": null, "url": "https://…", "img": null, "shop": "Gloria Jeans"}],
 "text": "HTML-текст поста"}
```

## Лук-ролик по просьбе Ирины (Higgsfield)

Только **по просьбе**: Ирина присылает боту фото своих вещей (альбомом — бот собирает его в одну просьбу, `photos`
в `data/requests.json`) и просит собрать лук. Никаких автоматических постов с Higgsfield, ролики по расписанию не делаем.
Просьба — лук-ролик, если в ней **2–6 фото вещей** и текст про лук/образ/ролик/«собери» (или текста нет). Одно фото
или просьба без фото — обычный черновик, как раньше. Ирине и в канал уходит ролик, превью владельцу не показываем.

**Кто делает:** отдельная ежечасная задача «лук-ролики по просьбам» (с коннектором Higgsfield). Если в твоём запуске
инструментов `mcp__higgsfiled__*` нет (обычная задача с черновиками), лук-просьбы **пропусти и оставь со `"status": "new"`** —
их заберёт задача с Higgsfield. Не делай по ним обычный пост и не меняй их статус.

**Нужны:** коннектор Higgsfield (инструменты `mcp__higgsfiled__*`, загрузи их через ToolSearch) и фото просьбы в репозитории
(бот кладёт их в `data/requests/`, они появляются в `main` через ~минуту после просьбы).

**Порядок (стоимость одного лука ≈ 10 кредитов; тариф Starter — 270 кредитов в месяц):**
1. `balance`. Меньше 40 кредитов — ролик не делай: сделай обычный черновик `album` из её фото (без Higgsfield) и в тексте
   ничего не обещай про видео. Не больше **2 лук-роликов в день**, остальные просьбы оставь со `"status": "new"` до завтра.
2. Посмотри фото просьбы (Read). Запиши, какие вещи видишь (верх, низ, верхняя одежда, обувь, сумка, аксессуары).
3. Загрузи фото в Higgsfield: `media_import_url` со ссылкой
   `https://raw.githubusercontent.com/Grach31/irina-mods/main/<путь из photos>` (репозиторий открытый, из облака Higgsfield
   файл заберёт сам; напрямую загрузить файл из облака нельзя).
4. Картинка-лук (`generate_image`, `model: "nano_banana_pro"`, 3:4, ~2 кредита), все фото как `image` (роль подставится
   сама). Промпт: flat-lay, готовый образ на тёплом бежевом бесшовном фоне, вещи разложены как комплект
   (верхняя одежда, верх, низ, обувь, сумка), мягкие тени, каждая вещь точно как на референсе (цвет, крой, фурнитура),
   без людей и текста, без лишних вещей. Если вещей меньше 3 — одна вещь в центре, остальные рядом.
5. Дождись результата (`jobs_wait`), возьми ссылку `result_url`. Одновременно не больше 2 задач, иначе лимит.
6. Видео (`generate_video`, `model: "kling3_0_turbo"`, 9:16, 5 с, 720p, ~7,5 кредита, `start_image` = картинка из шага 4,
   `declined_preset_id: "24bae836-2c4a-48e0-89b6-49fcc0b21612"`). Промпт: плавное появление и вращение — вещи мягко оживают на
   бежевом фоне, камера медленно наезжает, мягкий свет, вещи не меняют форму и цвет, без людей и текста. Одна повторная попытка,
   если задача `failed`; если снова — отправь Ирине только картинку (черновик без `video`).
7. Сначала положи черновик с `"hold": true`: бот нарисует превью (картинку) в `drafts/img/<id>.jpg` и не отправит Ирине.
   `git pull`, посмотри превью (Read): вещи на месте, не искажены, нет лишнего и текста — убери `hold`, запушь. Если вещи
   искажены или пропали — перегенерируй картинку один раз (другой промпт), иначе пришли обычный `album` из её фото.
   Видео бот скачает по ссылке в момент отправки (она живёт минуты), а в канал уйдёт сохранённым `file_id`.

```json
{"id": "2026-11-03-look-r123", "type": "item", "slot": null, "request_id": "r123", "hold": true,
 "image": "https://…/flatlay.png", "video": "https://…/clip.mp4",
 "items": [{"name": "Тренч с кожаным воротником", "price": null, "url": null, "img": null, "shop": null}],
 "text": "HTML-текст поста"}
```
Тип `item`: `image` — обязательное (путь в репозитории или ссылка, это превью в `drafts/img/`), `video` — необязательное
(ссылка на mp4 до 48 МБ). Есть `video` — Ирине и в канал уходит видео, нет — картинка. `items` — вещи для текста;
цен и ссылок нет, если Ирина не написала их в просьбе.

**Текст:** голос Ирины, 2–4 строки, список вещей по тому, что видно на фото (без выдуманных брендов и цен),
вопрос подписчицам в конце, до 900 символов. Не выдумывай ничего о том, где Ирина это носила или купила.

## Фото для карточек (история моды и новости)

В `card.images` у каждого фото один источник. Бот сам скачивает фото, берёт автора и лицензию и отбрасывает несвободные:
- `"commons": "Имя файла.jpg"` — Wikimedia Commons;
- `"met": 12345` — The Met Open Access, номер объекта из ссылки `metmuseum.org/art/collection/search/12345`
  (огромная коллекция костюма: Chanel, Dior, Balenciaga, Schiaparelli, Vionnet…);
- `"cleveland": "1995.123"` — Cleveland Museum of Art Open Access (id или инвентарный номер);
- `"openverse": "<uuid>"` — Openverse: свободные фото Smithsonian, Rijksmuseum, Europeana, Cooper Hewitt, Flickr и др.
  (id из ссылки `openverse.org/image/<uuid>`). Rijksmuseum, Smithsonian, Europeana, LACMA, Cooper Hewitt ищи на их
  сайтах и через Openverse; если фото там свободное (PD, CC0, CC BY, CC BY-SA), бери через `openverse`
  или через `"url"` с подписью в `card.credits`, только если сам проверил автора и лицензию;
- `"url": "https://..."` — прямая ссылка, подпись пишешь сам в `card.credits`.
Платные фотобанки (Getty, Shutterstock и т. п.) не использовать. Из облака эти сайты часто не открываются —
ищи через WebSearch/WebFetch, а картинку проверяй по превью бота (`"hold"`).

## История моды

- Повод: событие, которое случилось **в этот день** (дата публикации) в истории моды; если такого нет — событие этого месяца
  с круглой датой. **Факт и дату проверь по надёжному источнику** (WebSearch/WebFetch) и положи ссылки в `sources`. Не выдумывай.
- Фото только свободные: Commons и музейные источники выше. Из облака Commons не открывается, поэтому в `images` пиши **название файла**
  (`"commons": "Имя файла.jpg"`, без `File:`; найти можно через WebSearch — страницы `commons.wikimedia.org/wiki/File:...`).
  Бот сам берёт ссылку, автора и лицензию из API Commons, отбрасывает несвободные (всё, кроме PD, CC0, CC BY, CC BY-SA)
  и пишет подпись «Фото: автор, лицензия» на карточке. `card.credits` оставь пустым. Старый вариант `"url"` тоже работает,
  но только если ты сам проверил автора и лицензию.
- **Проверка картинки (обязательно для фото с Commons):** положи черновик с `"hold": true` и запушь. Бот (за 1–2 минуты)
  нарисует карточку в `drafts/img/<id>.jpg`, **не отправляя её Ирине**, и запишет итог в `state/state.json` → `held.<id>`
  (`preview_ready` или `error` с причиной). Делай `git pull` раз в ~30 секунд, пока там не появится этот id с новым `at`,
  затем посмотри картинку (Read). Подходит — убери `"hold"` из черновика, закоммить и запушь: бот отправит Ирине.
  Не подходит или `error` — поменяй файл в `commons` (черновик изменился — бот перерисует). После 3 неудач убери фото
  (`"images": []`) и отправь без него. Если бот не отвечает 10 минут — отправь без фото.
- На карточке 1–4 фото: 1 — во всю ширину, 2 — рядом, 3 — одно большое слева и два справа, 4 — сетка 2×2.
- **Фото к фактам.** Один факт — одно фото, поэтому в посте не больше 4 фактов, и фото идут в том же порядке, что факты.
  Лучше всего — **точное фото факта**: пишешь «Шанель придумала маленькое чёрное платье» — фото именно этого платья
  (или вещи этой модели/года), а не портрет Шанель; «Диор показал New Look» — снимок с того показа или костюм Bar.
  Проверяй по описанию файла (что изображено, год, дизайнер, коллекция). Если точного свободного фото нет,
  можно **общее по теме** (портрет дизайнера, дом моды, вещь той же эпохи), но текст не должен выдавать его за ту самую
  вещь. Сначала ищи точные фото и выбирай факты, к которым они нашлись; общие — только чтобы закрыть пробел.
- Текст: 3–4 коротких абзаца, без занудства, в конце вопрос.

## Новости модных домов

Раз в день (`"type": "news"`, `"daily": true`, `"slot": null`) — свежая новость мировых модных домов: новая коллекция или
показ, интересная вещь, коллаборация, тренд (Dior, Chanel, Gucci, Prada, Miu Miu, Saint Laurent, Louis Vuitton,
Bottega Veneta, Loewe, Balenciaga и т. п.).
- Новость не старше ~2 недель, не повторять дом/событие, которые уже были в `drafts/` за последние 7 дней.
- Факты (дата, место, дизайнер, детали вещей) — из надёжных источников: сайт самого дома, Vogue, WWD, Business of Fashion,
  Numéro, W и т. п.; ссылки в `sources`. Не выдумывай.
- Текст: 3–5 коротких абзацев голосом Ирины, вещь или образ описать красиво и конкретно (ткань, силуэт, цвет, с чем носить).
  **Без цен и без ссылок на магазины.** В конце можно вопрос к подписчицам. Подпись не длиннее 900 символов.
- Фото: 1–4 фото **с официального сайта дома** (страница показа/коллекции/новости) через `"url"`, в `card.credits` —
  «Фото: Dior» (название дома). С чужих сайтов, блогов, Getty и фотобанков не брать. Если на официальном сайте фото не
  достать — фото из свободных источников по теме (см. «Фото для карточек») или пост без новинки на фото не делать.
  Решение владельцев канала: идём на риск с фото брендов; если пост удалят по жалобе — перестаём и переходим на превью ссылки.
- На карточке в `year` — название дома крупно, если оно короткое (до ~8 букв: Dior, Gucci, Prada, Miu Miu, Loewe);
  длинное (Saint Laurent, Bottega Veneta) — в `title`, а в `year` сезон или год.
- Через `"hold"` так же, как «История моды»: посмотри превью и проверь, что на фото именно те образы, о которых текст.

```json
{
  "id": "2026-10-19-news-dior",
  "type": "news",
  "daily": true,
  "slot": null,
  "hold": true,
  "card": {"kicker": "НОВОСТИ МОДЫ", "year": "Dior", "note": "весна–лето 2027", "title": "Коротко о главном",
           "images": [{"url": "https://media.christiandior.com/...jpg", "fy": 0.15}],
           "credits": "Фото: Dior"},
  "text": "HTML-текст поста",
  "sources": ["https://www.dior.com/...", "https://..."]
}
```

## Формат товарных подборок — Telegram-альбом (с 11.11.2026)

- Для обычных подборок с 2–4 товарами (`items`) бот автоматически отправляет **каждое каталожное фото отдельно** одним Telegram-альбомом. Не собирать эти товары в единый коллаж 2×2.
- В ленте Telegram альбом отображается сеткой; по нажатию фотографии открываются крупно и листаются свайпом.
- Одна общая подпись к альбому: названия, цены и проверенные ссылки на каждый товар в порядке фотографий.
- Согласование Ириной обязательно: альбом сначала приходит ей, публикация в канал только после её кнопки «Опубликовать». Не обходить модерацию.
- `looks`, `news`, `history`, `item` и явные `album` сохраняют свои специализированные форматы.

## Единый стандарт фотоальбомов (11.11.2026)

- **Образы** (`type: looks`): каждый готовый образ публиковать **отдельным Telegram-альбомом**. Первое фото — эстетичный флэтлей полного комплекта; следующие фото — исходные каталожные фотографии каждой вещи по отдельности и в том же порядке. Один образ = 1 альбом (обычно 4–6 фото, максимум 10). Все альбомы одного черновика согласовываются Ириной одной кнопкой. Не объединять несколько образов в коллаж.
- **Новости моды** (`type: news`) и **история моды** (`type: history`): не использовать фотоколлажи/старые карточки-сетки. Добавлять 2–6 самостоятельных релевантных фото по теме (максимум 10), чтобы их можно было открывать и листать. Первым ставить наиболее сильный и точно соответствующий теме кадр. Не добавлять нерелевантные фото ради количества; если проверенное фото только одно, допустима одиночная фотография.
- Исторические фото — только с разрешённой лицензией (Commons/музейные CC0 и т. п.), с проверкой автора и условий использования; указывать атрибуцию. Фото новостей — официальные материалы при наличии права использования, проверять первоисточник, не выдавать чужие фотографии за свободные.
- Подпись — достоверный редакционный текст и источники; для образов — название, магазины, цены и ссылки на каждый товар. Следить за лимитом Telegram на подпись к фото (1024 символа). Если текст длиннее, разделять его на подпись и отдельное текстовое сообщение, а не обрезать смысл или ссылки.
- **Никаких автоматических публикаций без нажатия Ирины «Опубликовать»**. Для многосоставного поста одобрение распространяется на все альбомы черновика.
